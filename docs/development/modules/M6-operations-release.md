# M6 生产运行与发布实施规格

状态：待实施；依赖M0～M5，运行参数与真实环境按[决策登记](../decision-register.md)确认。依据[运维基线](../../operations.md)。

DP2已列出[M6-01～06任务](../roadmap-dp2.md)：M4-01后可准备环境/备份协议，真实备份、恢复与容量按各项依赖执行，不等M5结束才开始设计。M6-05交付发布候选，M6-06仍需独立生产授权。

## 1. 范围与环境

完成Staging/Production独立配置、备份/恢复、轮换、持久任务可观测性、压测、发布/回退与演练证据。生产部署是另一个实际任务，本轮制作规格不执行部署或购买资源。

配置必须有owner、环境别名、版本及漂移检查；不在仓库记录真实Secret。Production不共享Staging用户、Code、Key、Storage或SQL凭据。

## 2. 联合备份

实现每日DB一致快照+不可变对象清单+hash验证+独立备份存储的manifest。屏障阻止物理删除，不阻止新上传；快照中的active对象必须完整。manifest记录恢复点、对象版本、配置/迁移版本、校验、完成状态。

备份屏障与job lease持久化；失败/超2小时先把恢复集判失败再解除屏障，不将部分集标成功。备份任务凭据独立，主存储与备份成本分别统计。

目标RPO24小时、RTO4小时为初始值，必须经实际演练证明；不要把仅启用PITR当对象已备份。数据保留默认值在生产启用前由所有者确认。

## 3. 恢复演练

隔离项目恢复manifest对应DB与对象，禁外发邮件/业务流量，验证hash和完整性；重应用独立保存的删除墓碑。恢复旧Auth会话和Key必须失效，恢复出的未用旧码禁用，避免重复兑换。

恢复点后数据只有可信独立记录才能按operationId补录，否则明确记录允许RPO内的丢失与人工补偿，不凭估计补写Ledger。

重新配置SQL角色密码、Secret、Origin、job lease、上传unknown和删除状态；按G6回归清单验证。演练记录开始/结束、错误/重试、丢失窗口、hash差异和数据状态。

## 4. 轮换与恢复入口

Platform Key遵循新建→部署→成功调用确认→撤旧；HMAC旧版本verify-only，无法无明文迁移；Secret/SQL/备份凭据各自测试。

管理员恢复用限时recovery角色与基础设施访问：新专用用户先完成MFA，原子替换singleton，撤销旧session/proof，轮换接触过的Secret并关闭恢复入口。Auth故障期间不开免认证Admin。

runbook要给出经固定工具验证的真实命令、必要权限、预期输出及回退点，不能只列概念。所有生产清除/恢复动作有独立操作任务和明确授权。

## 5. 性能与监控

按确认的目标平台数/负载运行授权压测，初始100rps持续15分钟，p95<=500ms、错误率<1%；记录实例/数据库资源和成本。上传压测包括1MiB、有界接收并发和内存上限。

指标包括授权延迟、DB连接与锁、兑换冲突、限流、unknown文件/占用、删除积压、任务lease、备份年龄/失败及恢复校验。告警必须实际送达测试渠道，有对应runbook与owner。

容量不满足时优化连接/索引/host或调整承诺负载，不通过缓存授权或释放未知对象配额换取“通过”。

## 6. 发布和退出标准

G0-S/G1/G2-S/G3/G4-S/G5-L/G5-P先通过，X01～X06及默认参数已按需要确认，再验V-OPS-01/02/03。代码和配置固定版本，迁移expand/contract顺序与应用兼容。

发布清单包含backup manifest、校验结果、轮换/恢复报告、依赖与license、未解决问题、回退/forward-fix路径和告警。未解决安全P1、未知数据丢失或失败恢复路径不完整时不开放生产。

发布后检查Auth、Principal、兑换、上传/下载/删除、任务、告警；观察窗口和回退阈值按真实部署方案记录。GitHub push与CI成功不代表生产已部署。
