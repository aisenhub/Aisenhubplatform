## 实施

- `supabase/config.toml` 启用 Local transaction pooler，端口 `54329`、`pool_mode = "transaction"`。
- 根 devDependency 固定 `postgres@3.4.3`，Node 与 Deno 均以 `prepare: false` 连接；这是 transaction pooler 的必要设置。
- `tests/spikes/sql/role-probe.mjs` 只使用本地 postgres bootstrap 创建随机临时角色、NOLOGIN owner、隔离 `spike_private` schema 和一个允许函数；实际验证连接使用 account/admin/job executor，不使用 service-role 绕过。
- `tests/spikes/sql/edge-pooler.ts` 用 `npm:postgres@3.4.3` 从 Deno 直接通过 transaction pooler 调用相同私有函数。
- 探针结束删除隔离 schema、函数和临时角色；密码只存在进程环境和本次连接 URI，不写文件或输出。

## 限制

- 这只是隔离测试 schema/role，不是 M1 生产迁移；没有向 `auth.*` 授予业务 executor 权限，也没有修改 Supabase Auth 内部表。
- 首次启用 pooler 时，`pooler-dev` tenant 必须写入用户名（`role.pooler-dev`）；否则 Supavisor 明确返回缺少 tenant identifier。该连接格式已写入探针而非散落在业务代码。
- 旧本地 PostgreSQL 17 卷与固定 PostgreSQL 15 镜像不兼容，未删除旧卷；本次使用 `aisenhub-platform-auth-local` 隔离卷，探针完成后容器已停止。
