## 结果

T07 验收：PASS（Local transaction pooler）。未实现完整兑换领域，探针只验证公共事务边界。

## 实施

- 新增 `tests/spikes/txn/two-connection.mjs`，建立隔离 `spike_txn` schema、account state、idempotency 和 audit 测试表，以及一个受限 `SECURITY DEFINER` 原子入口。
- 两个独立 `postgres@3.4.3` 客户端通过 Local transaction pooler 连接，均关闭 prepared statements；并发调用使用 `Promise.all`，没有用睡眠碰撞。
- 入口在同一数据库函数内按账户行 `FOR UPDATE`，先检查同 key/hash，再写 pending/result/audit；故障点在 audit 后抛错，验证整个函数语句回滚。
- 每次探针结束删除 schema、表、函数和临时角色；本地容器已停止。

## 实际验证

| 用例/检查 | 结果 | 证据 |
|---|---|---|
| 同账户不同 operation 并发 | PASS | 两次均生效，账户最终余额为 2，行锁串行化 |
| 不同账户并发 | PASS | account-a/account-b 独立完成，无全表锁阻塞 |
| 同 key、同 hash | PASS | 两次调用仅一次 applied，第二次返回既有结果，余额只增加一次 |
| 同 key、异 hash | REJECTED | `idempotency_conflict` 业务拒绝，原结果不变 |
| 业务/SQL 异常回滚 | PASS | audit 后注入异常，余额、idempotency、audit 均无半条写入 |
| 提交后响应丢失重放 | PASS | 首次结果丢弃后同 key 重放返回原结果，无重复 audit |
| lock timeout | PASS | `1000ms` |
| statement timeout | PASS | `2000ms` |
| isolation | PASS | PostgreSQL `READ COMMITTED` + 账户行锁 |
| SP-TXN | PASS | 双连接、锁、幂等、回滚和重放完整通过 |
| V-TXN-01/02 原型 | PASS | 同/异 hash、业务拒绝、异常回滚、Audit 一致提交覆盖 |

## 边界

该探针不代替 M1 生产迁移，也不实现 Ledger/Entitlement；它证明后续领域函数必须把业务写入、幂等和审计放在同一数据库原子边界。跨 Storage 的 unknown 状态仍由 M4 文件状态机处理。
