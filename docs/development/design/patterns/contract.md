# 页面模式契约

## 1. Pattern 的职责

Pattern 说明任务中常见的组织关系，例如：范围/筛选/列表/详情、草稿/保存/错误、工作区主动作/次动作、权威结果/来源/状态。它不持有业务 API、数据库字段或权限规则。

## 2. 先任务，后组件

建立页面时先回答：

- 用户当前要完成什么？
- 哪个对象和 scope 是权威上下文？
- 哪些状态来自服务端/领域？
- 什么需要保留在 URL、什么只是临时 UI 状态？
- 失败、取消、unknown outcome 后如何继续？

再选择 Pattern 和标准组件；不能从“想用 Card/Sheet/Table”反推任务。

## 3. 模式与业务分离

Pattern 可以规定“详情关闭后恢复焦点”，但不能规定账户删除 API；可以规定“保存失败保留草稿”，但不能决定自动保存还是显式保存。真实业务规则以 Spec/Architecture/API 为准。

## 4. 提取门槛

只有多个真实页面出现相同结构、状态和交互契约时才提取组合组件。两个页面看起来相似但数据/行为不同，不要求强行进入万能 renderer 或 schema-driven page generator。
