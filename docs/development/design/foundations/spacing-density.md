# 尺度、间距与密度

尺度系统服务信息组织和可操作性，不是把整个页面等比缩放。

## 语义尺度

后续 Theme 可以按真实需要维护：普通/小控件、图标、菜单/列表行、字段间距、分组间距、页面/面板间距等语义角色。只有重复关系真实存在才增加 token，不为“完整 token 表”制造无消费者变量。

## 密度

密度是**任务上下文**，不等同于组件 `size`、浏览器 viewport 或页面 zoom。

- 桌面管理工作台可以高密度，但不得牺牲键盘焦点、文字可读和必要点击范围。
- 阅读、危险确认和复杂表单可以比密集列表需要更多空间。
- 控件 `size` 表达组件用途；density 表达当前工作区整体节奏，两者不能互相冒充。
- 宽屏也可能使用触控，不能仅凭断点判断可点击目标大小。
- Portal/Overlay 如果属于某个局部密度上下文，应消费同一呈现上下文，但公共 UI 不因此持久化业务偏好。

## 专业/业务度量

Table 行高、图表轴、代码编辑器、可视化画布等确有专业度量时可以由各自 owner 管理，不强行并入普通控件密度。阶段 03 优化时要明确哪些是普通 UI，哪些属于专业内容。

## 验证

至少检查长中英文、窄视口、200% 文本放大、键盘/触控、Dialog/Popover、Table 横向区域和错误内容。固定高度不得裁掉多行错误或必要操作。
