## 必读顺序

1. 根 `AGENTS.md`、`docs/README.md` 和 `docs/agents.md`。
2. 当前 Proposal 的 `design.md`、`plan.md`、本阶段计划和 `verification-record.md`。
3. 相关 `docs/architecture/`、`docs/reference/`、源码、迁移、测试和构建脚本。

## 执行提示词

```text
你正在实施 [Proposal 名称] 的 [阶段编号/名称]。

只执行本阶段计划和已满足依赖的必要工作。先核对当前分支、起始 commit、工作区修改和远程地址；不要覆盖用户已有修改。以代码、迁移、配置和实际测试入口核对事实，不把计划或旧记录当成实现证据。

遵守当前 Proposal 已冻结的数据、接口、状态、权限、并发、失败恢复和文件所有权约束。复用已有领域入口和共享能力，不在 BFF、Admin、页面、SDK 或任务中复制领域算法。未实现能力不得做成假按钮、假数据或假进度。

完成后运行本阶段列出的真实验证命令，区分通过、失败和未运行；代码改变后重新判断旧验证是否仍覆盖。更新 verification-record.md，检查 diff 和敏感信息，创建阶段 commit 并 push，核对远端 commit 后再标记已交付。

遇到架构冲突、数据风险、外部依赖、缺少权限或需要用户决定的事项，停止依赖该事项的工作，记录证据、影响、已完成部分和继续条件。禁止 force push、重写历史、合并主分支、创建 Release、部署生产或变更费用。
```
