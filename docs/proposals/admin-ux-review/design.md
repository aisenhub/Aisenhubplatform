# Admin 操作体验改进

状态：Completed（本地交付；未发布）

关联：[计划](plan.md) · [当前前端](../../architecture/modules/frontends.md)

## 目标与范围

用户要求从管理员交互角度审查并修改 UI/UX，视觉方向由 Agent 决定，高频任务为平台与账户管理。仅进行本地验证。

使用任务账簿式工作区：深色导航、浅色数据表面、青色主操作；固定字号、紧凑搜索、清晰行结构。平台目录优先展示平台名称与标识、状态、激活策略和进入入口。概览突出常用任务与关注事项。管理员文案描述任务与风险，而非接口实现。

## 审查发现与实现

- 页面 API/合同说明占据注意力：主要页面说明改为任务语言，保留一次性密钥、交付、结果未确认等必要风险提示。
- 平台搜索占据独立大面板：收敛为紧凑工具栏，保留显式搜索、URL、清除与失败恢复。
- 账户行高风险动作过于突出：强调查看入口，关闭使用风险文本色；确认、理由、MFA 与提交协议不变。
- 中等屏幕快捷跳转按钮内容拥挤：图标模式延续到桌面断点，并提供始终可用的可访问名称。
- 键盘缺少跳过导航入口：新增跳到内容链接与可聚焦内容容器。
- 移动导航选择页面后缺少明确收起：路由变化后关闭抽屉，当前平台范围仍由 URL 决定。
- 表格滚动与键盘焦点不在同一容器：统一为有名称的单一滚动区域，提供窄屏提示、可见焦点与方向键滚动。
- 详情行填满整个抽屉造成过大间距：字段按自然内容高度从顶部排列。

## 边界

不修改 Auth、API、BFF、SQL、DTO、SDK、业务算法或依赖。不改变计费、权益、账户动作、敏感操作确认与 unknown outcome 语义。浏览器模拟测试只能证明前端呈现与交互，不能证明服务端联调。
