# D3 生命周期策略：给业务方的简明说明

D3 不是一个技术名词，而是三个“以后发生什么”的产品规则。它会影响暂停、删除、账务审计和旧 Plan 的购买入口，所以不能由代码默认猜测。

## 一句话版本

- 暂停：现在就停新购买，还是连已经买到的权益也马上停？
- 删除：账号删掉后，账务记录和个人信息分别留多久？
- 归档：Plan 下架后，旧用户的权益要不要继续，旧价格能不能被修改？

## 推荐选择

如果暂时没有特殊业务要求，我建议采用下面这组安全默认值：

1. 暂停立即阻止新购买和新权益，但已经成功购买的有限期权益继续到原结束时间；已付款订单继续结算，不静默丢失。
2. 删除时保留最小化账务/审计证据；个人信息在法定或财务保留期结束后匿名化。具体“几年”先由法务/财务确认，不在代码里猜。
3. Plan 归档后停止新 Checkout，但历史订单、价格快照和已有权益继续可读和生效；新商业条款发布新 Plan，不修改旧 Plan。

## 需要你只确认三句话

- 暂停时，已有权益是否继续到期？（推荐：继续）
- 删除后，具体保留年限由谁确认？（推荐：法务/财务给出期限后再配置）
- 归档 Plan 是否禁止新购买但保留旧权益？（推荐：是）

在这三句话确认之前，我可以完成本地接口、锁序、测试夹具和文档准备，但不会把删除年限或撤权行为写成不可逆的生产规则。
