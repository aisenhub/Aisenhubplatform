# ADR-0004：本地测试作为最高验收环境

状态：Accepted。Supersedes [ADR-0003](0003-local-verification-release-gates.md)。执行规则统一维护在[开发与发布流程](../guides/development-release-workflow.md)。

## 背景与决定

用户于2026-10-05明确要求：以后开发的项目测试最高只需要本地 Supabase，测试通过即可上线。

- 保留 R0–R3 风险分类及适用本地静态、构建、单元、API、浏览器、权限、并发、恢复和消费者验证。
- R2/R3 的最高测试环境为本机 Docker Supabase；不再要求 Hosted Staging、远程 Provider、真实交易或额外 CI 验收。Provider 行为在本地 Mock 验证。
- 本地适用测试通过即可进入上线流程；CI 可以复跑同套本地检查，没有 CI 结果不增加发布阻塞。已有仓库分支保护不得绕过。
- 测试结论绑定最终候选，失败必须修复并复测，不能删除断言、放宽权限或把未运行写成通过。
- Local 与 Production 隔离。目标、配置、迁移兼容、恢复清单和已有发布授权仍属于部署核对；Git、生产部署、收费开关和真实交易分别记录。

## 边界

本地通过不等于远程 Provider 或生产运行事实已验证；外部联调和生产观察如未执行记为 NOT_RUN，不反向成为代码上线前的额外测试门槛。生产部署按用户实际派发与既有授权执行，不因测试规则变更擅自收费、发起交易或执行破坏性操作。
