# ADR-0002：开发环境、任务分支与按风险发布

状态：Accepted。项目采用单人单机、Agent执行开发的方式。环境、分支和发布的详细规则统一维护在[Agent开发与发布流程](../guides/development-release-workflow.md)，所有Agent开始任务必须阅读。

## 背景

项目跨Auth、数据库领域过程、Storage、Provider、Webhook、后台任务和多平台BFF，本地测试不能完整证明实际托管配置与外部链路。使用短期任务分支隔离改动，在证据满足后自动合并，生产发布保留独立门槛。

## 决定

- 采用三个互相隔离的数据环境：Local Docker、独立Hosted staging项目、独立Hosted production项目；Admin和平台前端分别连接对应环境。
- 标准流程为Local → Staging → 生产前门槛 → Production。CI保留质量检查职责，不是独立业务环境，不因此新增自动部署。
- 纯文档/测试等R0不部署应用；严格限定的R1展示修改允许跳过staging，但生产部署仍经过精简门槛。一般功能R2和核心安全R3必须staging。
- 详细分类、验证、门槛、隔离、回退与授权规则唯一维护在[开发与发布流程](../guides/development-release-workflow.md)，Agent必须先读。
- Git提交/推送与部署分开；本决策不授权创建资源、费用、真实交易或生产操作。
- 只保留长期main与短期codex/任务分支，默认一次一个任务，不强制长期develop分支或第二人审批。需要触发CI或满足分支保护时使用PR。
- 用户长期授权Agent为已派发任务创建分支、提交、推送；所有分级验收及合并条件满足后自动合并main并推送，不逐次询问。main存在自动生产部署绑定时，合并前必须已有生产授权并完成生产门槛；绑定未知不得擅自触发。

## 文档边界

根AGENTS及开发、测试、运维入口引用同一流程，不维护第二套分支或发布规则。[ADR-0001](0001-platform-account-boundaries.md)维护领域、权限和数据保护边界。规则仅保留当前内容，任务执行证据与失败记录独立保留，不作为过程说明删除。

## 代价与验证边界

增加staging配置维护和验收时间，可先用共享小规格项目，不要求为每个平台/PR创建独立Supabase。配置漂移、测试数据污染和证据版本失效必须按流程防范。免费/付费选择另行决定。

Accepted仅表示规则已采用，不代表云项目、Hosted部署、全部测试、CI发布门槛或生产观察已实施。环境不可用时完成独立本地准备，所需Hosted验收与发布保持阻塞。
